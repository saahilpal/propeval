# 04 — Functional Requirements

All requirements are uniquely numbered, testable, and mapped to their verification method and release tier.

## 1. Prompt, Fixture & Dataset Management
* **FR-01 (Immutable Prompt Registry):** Users and CI pipelines must register immutable prompt versions containing `system_prompt`, `model_id`, `temperature`, `tools_schema` (JSON Schema), and `parent_version_id`, deduplicated by content SHA-256.
* **FR-02 (Versioned Property Truth Fixtures):** Users must upload versioned real-estate project fact fixtures (`project_name`, `city`, `rera_id`, `carpet_area_sqft`, `price_bands_inr`, `floor_rise_per_floor`, `possession_date`, `payment_plans`, `effective_from`, `supersedes_id`). Newer effective dates strictly override older facts.
* **FR-03 (Stratified Versioned Scenario Suites):** The system must manage immutable YAML scenario suites stratified across `city`, `price_band`, `language_mix` (`en`, `hi`, `hinglish_roman`, `hinglish_devanagari`), `campaign_type` (qualification, site visit, callback, reactivation, collections), and `friction_type` (cooperative, skeptic, budget-switcher, angry DNC, interrupter).
* **FR-04 (Production Replay Import with DPDP Redaction):** Users must import anonymized production transcripts (JSON/CSV/Twilio-Exotel export) into regression suites. All imported text must pass through the in-VPC Presidio PII redactor (`<IN_PHONE_n>`, `<IN_PAN_n>`, `<IN_AADHAAR_n>`, `<BUYER_NAME_n>`) prior to storage.

## 2. Hybrid Conversation Simulation & Perturbation
* **FR-05 (Hybrid FSM + LLM Buyer Simulation):** Each scenario must execute a deterministic Finite State Machine (FSM) agenda controlling when the simulated buyer reveals slots (budget, BHK, timeline), raises objections, or triggers DNC/hang-up, while an LLM renders natural Hinglish/Hindi/English utterances constrained to the current FSM state.
* **FR-06 (Paired Seed Execution):** Every comparison run (`baseline_prompt_id` vs `candidate_prompt_id`) must execute both prompt versions against the exact same $N$ scenario seeds, FSM transitions, project fixtures, and repeated trial count $K \in \{1, 3, 5\}$.
* **FR-07 (Domain-Aware 8 kHz ASR & Tool-Fault Injection):** Scenarios must support configurable perturbation profiles injecting realistic Indian telephony ASR confusions (`"crore"` $\to$ `"core"`, `"BHK"` $\to$ `"B K"`, dropped Hindi postpositions, mid-sentence barge-in truncation) and deterministic mock tool failures (`503 Service Unavailable`, timeout, empty inventory) to verify graceful agent recovery.
* **FR-08 (Pluggable Target Agent Execution):** PropEval must support both `LocalLLMAgentAdapter` (calling an LLM with mocked real-estate tools) and `RemoteWebhookAgentAdapter` (calling a customer's live staging agent over SSRF-protected HTTPS), with a clean interface for future `PipecatAudioAgentAdapter`.

## 3. Non-Compensatory Multi-Tier Evaluation
* **FR-09 (Layer 1 — Deterministic Code Assertions):** Every completed conversation must be graded deterministically on: (a) Indian currency & unit canonicalization (`"1.2 cr"` == `"120 lakh"` == `"ek crore bees lakh"` == `12000000`), (b) structured lead-extraction F1 against scenario ground truth, (c) strict tool-call JSON Schema & argument validity, (d) DNC compliance (calling `mark_dnc` and terminating within 1 turn of refusal), (e) zero "invented actions" (forbidding verbal booking/WhatsApp confirmation when the corresponding tool was not called or returned an error), and (f) spoken conciseness limits (max words/turn).
* **FR-10 (Layer 1B — Metamorphic Invariance Suite):** PropEval must execute linked metamorphic scenario pairs (e.g., `"1.2 cr"` vs `"120 lakh"`, English vs Romanized Hinglish) and assert identical canonical slot extraction and retrieved property IDs.
* **FR-11 (Layer 2 — Grounded Property Fact Verification):** PropEval must extract numeric/date/RERA claims from agent utterances and verify exact entailment against the active `project_fixtures` version, flagging stale or fabricated quotes as hard failures.
* **FR-12 (Layer 3 — Cross-Family Calibrated Rubric & Simulator-Fidelity Audit):** Subjective dimensions (objection handling, Hinglish register naturalness, empathy) must be graded as binary pass/fail questions with written rationales using a model family **independent** of the target agent, with position-swapped pairwise comparison (`(A,B)` and `(B,A)`). A separate simulator-fidelity check must quarantine rollouts where the buyer simulator violated its own FSM instructions.
* **FR-13 (Judge Calibration Management):** Users must upload a locked human-labeled golden calibration set (minimum 30 transcripts per rubric), compute Fail-class Precision/Recall, Cohen's $\kappa$, and per-variant TPR/TNR, and report bias-adjusted pass rates (Rogan–Gladen / PPI++).

## 4. Statistical Diffing, CI Gating & Failure Analysis
* **FR-14 (Tiered Statistical Reporting):** PropEval must compute paired Exact McNemar's test + Newcombe paired Wilson CIs (binary outcomes), Wilcoxon signed-rank + paired cluster/hierarchical BCa bootstrap CIs (continuous/ordinal outcomes), `pass^k` consistency, and Holm-Bonferroni / Benjamini-Hochberg adjusted $p$-values. Runs with $N < 50$ must be explicitly labeled `SMOKE_TEST_UNDERPOWERED` on statistical claims.
* **FR-15 (Non-Compensatory Release Gate & CLI):** The CLI (`propeval run --gate`) must exit non-zero (`exit 1`) if any hard deterministic gate regresses (DNC, RERA/pricing hallucination, invented action, schema error) OR if the primary metric regresses significantly after Holm-Bonferroni correction.
* **FR-16 (Cost Circuit Breaker & Partial Resumption):** Every run must enforce an atomic `max_budget_usd` cap and `max_turns` cap. Runs halted by budget or transient outages must support resuming only incomplete/failed cases without re-executing already-completed turns.
* **FR-17 (Live Progress & Failure Taxonomy Explorer):** The Web UI must stream per-job completion via SSE (`Last-Event-ID` resumable), display side-by-side V1 vs V2 diffs across all capability dimensions, and allow engineers to tag failure root causes by pipeline stage (`ASR_NOISE`, `SLOT_EXTRACT`, `FACT_HALLUCINATION`, `TOOL_CONTRACT`, `TONE_REGISTER`, `SIMULATOR_FAULT`).
