# ADR-008: Security Architecture — DPDP Act 2023 PII Redaction, Prompt-Injection Isolation & SSRF Egress

**Status:** Accepted | **Date:** 2026-11-19

* **Decision:** Implement four non-negotiable security boundaries: (1) in-VPC **Microsoft Presidio** redaction (custom Indian mobile, PAN, Verhoeff-validated Aadhaar rules) *before* DB persistence or external LLM calls; (2) randomized XML nonce framing + JSON Schema enforcement isolating untrusted transcripts from LLM judges; (3) per-tenant **AES-256-GCM KMS envelope encryption** + PostgreSQL `FORCE ROW LEVEL SECURITY`; and (4) **DNS-pinned HTTPS-only SSRF egress proxy** (`follow_redirects=False`, IMDSv2) for customer target-agent webhooks.
* **Requirement:** Satisfies FR-04 (safe production replay import), NFR-13 (DPDP Act 2023 compliance & 24h Section 12 erasure), NFR-14 (secret & tenant isolation), and NFR-15 (SSRF zero-bypass).
* **Alternatives:** (1) **Regex-only PII scrubbing**; (2) **Third-party cloud PII redaction API**; (3) **Application-layer `WHERE tenant_id = ?` without PG RLS**; (4) **Direct `httpx` calls to customer webhook URLs with hostname blocklists**.
* **How the alternatives work:** Regex-only scrubs fixed patterns but misses free-text Indian names/addresses. Third-party PII APIs send raw transcripts outside the VPC. App-layer tenant filtering relies on developers never forgetting a `WHERE` clause. Hostname blocklists check URL strings before calling `httpx`.
* **Selection reasoning:** Real estate calls routinely contain spoken phone numbers, buyer names, PANs, and Aadhaar numbers regulated under India's [DPDP Act, 2023](https://www.meity.gov.in/static/uploads/2024/06/2bf1f0e9f04e6fb4f8fef35e82c42aa5.pdf). Presidio runs in-VPC (`ap-south-1`), preserves conversational structure with typed tokens (`<IN_PHONE_1>`), and uses Verhoeff checksums so 12-digit RERA/price numbers aren't falsely redacted. `FORCE ROW LEVEL SECURITY` guarantees DB-enforced multi-tenant isolation even under ORM bugs. DNS-pinned IP validation defeats DNS rebinding attacks that bypass naive URL string filters ([OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)).
* **Rejected alternatives:** Regex-only fails on buyer names/addresses; external PII APIs violate in-VPC minimization; app-only tenant filtering is one missed `WHERE` clause away from a breach; hostname blocklists are trivially bypassed via DNS rebinding or HTTP `302` redirects to `169.254.169.254`.
* **Trade-offs:** We gain enterprise/regulated Indian B2B readiness and protection against OWASP LLM01 judge hijacking. We accept ~15–30 ms per imported transcript for Presidio NLP inference and extra deployment complexity for the egress proxy subnet.
* **Failure modes:** Presidio NER false negatives on unusual regional Indian names (mitigated by custom Indian name gazetteer + ZDR LLM contracts); false positives redacting legitimate project names (mitigated by allowlisting active `project_fixtures.project_name` and `rera_id`).
* **Cost:** Presidio runs in-process/sidecar on CPU (~500 MB RAM); KMS API calls amortized via short-lived in-memory DEK caching; dedicated egress proxy adds ~$30–$50/mo in cloud staging/prod.
* **Revisit conditions:** Upgrade Presidio's spaCy/transformer NER model to an Indic-tuned NER model if Hinglish buyer-name recall falls below 95% on anonymized Huvo production transcripts; add mTLS client certificates if enterprise developers require private-link webhook connectivity.
