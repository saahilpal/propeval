# ADR-002: PostgreSQL `FOR UPDATE SKIP LOCKED` Queue + Hybrid Relational/JSONB Schema

**Status:** Accepted | **Date:** 2026-11-19

* **Decision:** Use **PostgreSQL 17/18** (`asyncpg 0.32.0`, SQLAlchemy `2.1.9`, Alembic `1.20.1`) as both the OLTP store and transactional job queue using `FOR UPDATE SKIP LOCKED` with 60 s leases, 20 s heartbeats, and monotonic `fence_token` CAS commits, paired with a hybrid relational + `JSONB` schema and `FORCE ROW LEVEL SECURITY`.
* **Requirement:** Satisfies NFR-05 (0% double-claimed active jobs, 0% split-brain commits), NFR-07 (crash recovery <=90 s with 0% duplicate LLM billing), NFR-08 (atomic USD budget cap), and NFR-14 (tenant isolation).
* **Alternatives:** (1) **Redis + Celery (`5.7.0`) / Dramatiq (`2.2.1`)**; (2) **Temporal (`1.36.1`)**; (3) **SQLite `3.54.1` (WAL)**; (4) **MongoDB** for document-oriented transcripts.
* **How the alternatives work:** Celery/Dramatiq push serialized task payloads into a separate Redis/RabbitMQ broker, requiring an outbox pattern to stay consistent with DB state. Temporal persists deterministic Event Histories in its own cluster. SQLite WAL allows concurrent readers with a single writer lock on local disk. MongoDB stores full nested conversations as BSON documents.
* **Selection reasoning:** PostgreSQL lets PropEval insert `eval_runs`, reserve `reserved_usd`, and enqueue `2*N*K` `eval_jobs` in **one ACID transaction**. Typed relational columns on `eval_jobs`, `conversation_turns`, and `assertion_results` allow fast B-tree aggregations and exact paired diffs without deserializing blobs, while `JSONB` (with `jsonb_path_ops` GIN indexes) accommodates flexible real-estate `project_fixtures` and tool traces. Partial indexing (`WHERE status IN ('QUEUED','RUNNING')`) keeps queue scans $O(\text{active jobs})$.
* **Rejected alternatives:** Celery has poor native `asyncio` ergonomics for high-concurrency LLM HTTP clients and introduces dual-write drift; Dramatiq is LGPL-3.0 and adds broker ops; SQLite WAL cannot scale across multiple horizontally autoscaled worker pods; MongoDB lacks `FOR UPDATE SKIP LOCKED`, strong relational joins for paired diffs, and native RLS.
* **Trade-offs:** We gain ACID transactionality, zero extra queue broker, and native RLS. We lose sub-millisecond in-memory queue latency (irrelevant when LLM turns take 2–30 s) and must actively tune PostgreSQL autovacuum on `eval_jobs`.
* **Failure modes:** Holding transactions open during LLM calls would exhaust connection pools (prevented by short <5 ms claim transactions + lease heartbeats); zombie workers waking after GC pauses could overwrite results (prevented by `WHERE fence_token = N` CAS commits); `eval_jobs` table bloat if autovacuum lags.
* **Cost:** Slightly higher SQL discipline (partial index static predicates, expand-and-contract Alembic migrations, aggressive autovacuum config); Valkey (`8.x`, BSD-3-Clause) is still used strictly for ephemeral RPM/TPM token buckets and SSE Pub/Sub.
* **Revisit conditions:** Replace `storage/queue.py` with Temporal (`1.36.1`) when sustained job transitions exceed **500/sec** or workflows require multi-day HITL sleeps; partition `conversation_turns` monthly past **10M rows**; offload cross-run analytics to DuckDB/Parquet or ClickHouse past **50M assertion rows**.
