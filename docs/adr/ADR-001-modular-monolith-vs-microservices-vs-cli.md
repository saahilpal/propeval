# ADR-001: Modular Monolith + PostgreSQL Queue vs. Microservices vs. CLI-First

**Status:** Accepted | **Date:** 2026-11-19

* **Decision:** Adopt a **Modular Monolith** (Python 3.12+ / FastAPI `0.165.0`) with strict internal package boundaries (`api`, `engine`, `evaluation`, `stats`, `security`), backed by a PostgreSQL transactional job queue, Valkey rate-limiting/SSE Pub/Sub, Next.js `16.4.6` UI, and a thin CLI client.
* **Requirement:** Satisfies FR-05–FR-17 (shared web diffing UI, live SSE streaming, CI/CD CLI gating, multi-tenant RLS, atomic budget caps) and NFR-01–NFR-08 (sub-90s smoke runs, crash recovery, solo/small-team maintainability).
* **Alternatives:** (1) **Option B — Event-Driven Microservices** (FastAPI + Temporal `v1.32.2` / Kafka + separate Simulator/Grader pools + PG + ClickHouse + S3); (2) **Option C — CLI-First Local/Serverless Runner** (Python/Promptfoo CLI + SQLite `3.54.1` WAL + DuckDB `2.0.0` + GitHub Actions artifacts).
* **How the alternatives work:** Option B isolates workflow orchestration in Temporal's durable Event History and streams high-volume assertion rows into ClickHouse MergeTree for analytical slicing. Option C executes eval loops locally or inside ephemeral GitHub Actions runners, writing to a single local SQLite WAL file and publishing static HTML reports.
* **Selection reasoning:** PropEval's workload is I/O-bound and bursty (<500 job state transitions/sec at startup scale). Option A provides ACID transactional consistency between run creation, USD budget reservation, job enqueueing, and turn persistence in a single database—while delivering a shared web UI for Prompt Engineers and founders that Option C lacks, at <10% of Option B's infrastructure cost (~$100–$350/mo vs ~$1,200–$4,000+/mo).
* **Rejected alternatives:** Option B introduces four data stores (PG, Temporal DB, ClickHouse, S3), workflow determinism constraints, and months of platform ops before delivering a single regression diff. Option C hits SQLite's single-writer lock under concurrency, lacks shared multi-tenant UI/RBAC for non-engineering QA, and provides no centralized longitudinal SPC monitoring.
* **Trade-offs:** We gain single-repo simplicity, ACID outbox guarantees, and one-command `docker compose` parity. We lose independent horizontal scaling of Simulator vs. Grader blast radii and native multi-day workflow sleep/resume until migrating to Temporal.
* **Failure modes:** High queue churn can cause PostgreSQL MVCC dead-tuple bloat on `eval_jobs` if autovacuum is misconfigured; heavy analytical queries on `assertion_results` can contend with OLTP job claims if run on the primary DB without a read replica or Parquet/DuckDB offload.
* **Cost:** Moderate initial engineering discipline to enforce clean module boundaries (`engine/` and `evaluation/` must never import FastAPI); ~$100–$350/mo managed cloud hosting in `ap-south-1`.
* **Revisit conditions:** Migrate orchestration to Temporal (`1.36.1`) if sustained queue transitions exceed **500/sec**, if multi-hour/multi-day human-in-the-loop grading pauses are required, or if Simulator webhook I/O and Grader pools need isolated autoscaling. Add ClickHouse if analytical queries exceed **50M assertion rows**.
